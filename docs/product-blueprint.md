# 个人工具模板：产品与界面蓝图

> 状态：设计基线（2026-08-19）  
> 适用范围：Next Fullstack Starter 的产品壳层、设置中心、业务模块组织与基础设施取舍  
> 视觉参考：[项目根目录 `DESIGN.md`](../DESIGN.md)，来源为 getdesign.md 的 Notion 独立分析

## 1. 结论先行

这个模板不应该继续沿用“通用后台管理系统”的信息架构。它更适合被定义为：

**一个面向单人或小范围本地使用的个人工具内核，默认只展示业务，账户、权限和系统能力收进设置。**

核心决策：

1. 主侧栏只放用户要完成的工作，例如首页、项目以及未来的笔记、任务、收藏等业务模块。
2. 左下角用户入口打开账户菜单；菜单第一项进入设置，另保留主题快捷切换和退出登录。
3. 个人资料、密码、外观、数据管理进入“个人设置”；用户、角色、系统状态进入管理员可见的“系统设置”。
4. 采用 Notion 启发的暖感极简，而不是复制 Notion：柔和画布、安静边框、克制色彩、内容优先、较高信息密度。
5. 页面不再默认套 Card。Card 只表示确实独立的对象或可交互单元；文档页、表格页和设置页主要依靠标题、留白、分隔线和背景层级。
6. “项目”保留为示例业务模块，但模板内核与示例业务必须清晰分层，使下一个项目可以删除示例而不伤及认证、设置和应用壳层。

## 2. 当前审计

### 2.1 已经做好的基础

| 领域 | 当前状态 | 结论 |
| --- | --- | --- |
| 技术底座 | Next.js 16、React 19、TypeScript、Tailwind v4、shadcn/ui | 保留 |
| 数据 | SQLite、Drizzle、迁移、外键、WAL、健康检查 | 保留 |
| 数据安全 | 在线备份脚本、备份后校验、数据库文件忽略提交 | 保留并补恢复/导出入口 |
| 身份 | Better Auth 邮箱密码、关闭公开注册、单管理员约束 | 保留 |
| 授权 | 页面、DAL、Server Action 附近重复校验；所有权落实到查询 | 保留 |
| 稳定性 | error、global-error、not-found、loading、health endpoint | 保留并统一视觉 |
| 质量 | Biome、TypeScript、Vitest、Playwright 桌面/移动用例 | 保留并扩展无障碍覆盖 |
| 偏好 | 主题、字体、内容布局、导航样式、侧栏模式的持久化基础 | 能力成熟，但缺少可发现的设置界面 |

### 2.2 主要产品问题

| 优先级 | 问题 | 影响 | 设计处理 |
| --- | --- | --- | --- |
| P0 | 业务、个人资料、用户和角色平铺在主导航 | 用户无法区分“做事”和“配置系统” | 主导航业务化，全部管理能力进入设置 |
| P0 | 偏好系统只有顶部主题按钮，没有设置中心 | 已有能力不可发现，也无法形成模板规范 | 新建 `/dashboard/settings/*` |
| P0 | 页面普遍使用同质 Card | 层级扁平、边框噪音大、像脚手架 | 建立 4 种页面模板，不再默认 Card |
| P1 | 顶部栏只有“本地工作台”和主题按钮 | 缺少当前位置、页面动作与移动上下文 | 改为面包屑/页面标题 + 上下文动作 |
| P1 | 首页展示“模板已就绪”等开发者信息 | 业务界面暴露模板说明 | 移到文档或“关于”，首页只留业务内容 |
| P1 | 桌面内容无限拉宽，移动只做纵向堆叠 | 可读性和密度不稳定 | 页面级宽度策略与移动信息重排 |
| P1 | 角色页是静态权限表，用户页却是业务入口 | 管理模型不一致 | 合并到“设置 > 用户与权限”分区 |
| P2 | 缺少全局检索/命令入口、最近访问 | 模块增加后导航成本快速上升 | 先预留命令面板接口，有 2 个以上业务域再启用 |
| P2 | 没有结构化日志、审计记录、CSP、限流 | 生产硬化不足 | 作为基础设施第二阶段，不塞进首轮 UI 重构 |

### 2.3 命名澄清

当前项目是 **local-hosted / local-data**：应用和 SQLite 运行在本机，但浏览器并不具备离线副本、同步与冲突解决。
因此文档可以继续使用“本地优先”表达部署偏好，但不要向使用者暗示它已经具备真正的 offline-first 或多端同步能力。

## 3. 产品原则

### 3.1 Business first

应用打开后只回答三个问题：我现在有什么、接下来做什么、怎样快速继续。认证实现、角色模型、数据库状态都不应出现在业务首页。

### 3.2 Personal by default

默认优化单人路径：快速进入、少配置、低维护、数据可导出和恢复。多租户、邀请、计费、公开注册、邮件和 OAuth 都是可选扩展，不属于默认内核。

### 3.3 Progressive disclosure

低频能力按层级隐藏：

- 高频业务：主导航直接可见。
- 个人配置：用户菜单进入设置。
- 管理配置：设置中的管理员分区，按权限显示。
- 开发与诊断：关于/系统页或 CLI，不进入普通业务页面。

### 3.4 Content over chrome

边框、阴影、色块和图标只用于解释关系。优先使用标题、留白、对齐和分隔线建立层级。

## 4. 信息架构

### 4.1 目标路由

首轮保留 `/dashboard` 前缀，避免为了命名产生无价值迁移。目标结构：

```text
/dashboard
├─ /projects                     示例业务模块
└─ /settings
   ├─ /profile                   个人资料
   ├─ /security                  密码与当前会话
   ├─ /appearance                主题、字体、内容宽度、侧栏
   ├─ /data                      导出、备份说明、数据位置
   ├─ /users                     管理员：本地账号
   ├─ /roles                     管理员：角色与权限说明
   └─ /about                     版本、运行模式、系统健康
```

兼容策略：旧的 `/dashboard/profile`、`/dashboard/users`、`/dashboard/roles` 先服务端重定向到新地址，经过一个版本后删除。

### 4.2 主侧栏

```text
[应用图标] 应用名
[搜索 / 命令面板]              可在业务模块增多后启用

工作区
  首页
  项目                           示例业务

固定/最近                       有真实数据后再出现，不展示空分区
  …

────────────────
[头像] 姓名                     点击打开用户菜单
```

规则：

- 侧栏配置属于应用壳层，不让每个业务页面自行定义。
- 分区没有内容时完全不渲染，避免“空模板感”。
- 图标只辅助扫描，不依赖图标传递唯一含义。
- 活动态使用柔和背景 + 明确文字，不使用粗重彩色条。
- 桌面默认宽度约 240px，可折叠；移动端使用 Sheet，内容区不保留空白侧栏。

### 4.3 用户菜单

点击左下角用户行打开菜单：

```text
姓名
邮箱 · 管理员/用户
────────────────
设置                    → /dashboard/settings/profile
────────────────
退出登录
```

“个人资料”不再作为主导航项。用户菜单只保留设置总入口，外观配置在设置中心完成；全局顶部栏提供浅色/深色快捷切换。

### 4.4 设置中心

桌面使用两栏结构，移动使用设置索引页 + 子页面：

```text
设置
├─ 个人
│  ├─ 个人资料
│  ├─ 安全
│  └─ 外观
├─ 数据
│  └─ 数据与备份
├─ 管理（仅管理员）
│  ├─ 用户
│  └─ 角色与权限
└─ 系统
   └─ 关于
```

设置页规范：

- 左侧导航 208–224px，右侧表单正文建议 640–760px。
- 一个页面一个保存语义；即时偏好可以自动保存并给轻量反馈。
- 使用水平 `Field`、`FieldGroup`、`FieldSet` 和 `Separator`，不要把每个设置项塞进 Card。
- 危险操作单独放页面底部的“危险操作”分区，不与常规字段并列。
- 管理员分区由权限决定是否渲染，同时页面、DAL 和 Action 继续独立鉴权。

## 5. 应用壳层与页面模板

### 5.1 全局壳层

| 部位 | 桌面 | 移动 |
| --- | --- | --- |
| 侧栏 | 固定 240px，可折叠为图标 | Sheet 导航 |
| 顶栏 | 44–48px，位置上下文在左，页面级次要动作在右 | 菜单按钮 + 当前页面标题 + 最多一个关键动作 |
| 内容 | 页面自己声明宽度策略 | 16px 外边距，关键动作可全宽 |
| 用户入口 | 侧栏底部 | Sheet 底部 |

### 5.2 四种页面模板

1. **Overview（首页）**：欢迎语、继续处理、最近项目、少量统计。统计不是默认卡片墙，只在对决策有帮助时显示。
2. **Collection（项目/用户）**：页标题 + 过滤/搜索 + 列表或表格 + 空状态。创建是唯一主动作。
3. **Document（详情/关于）**：窄内容列、清晰章节、长文可读。
4. **Settings（设置）**：设置导航 + 表单章节 + 分隔线。

页面宽度由模板声明：

- Overview / Collection：`max-width: 1200px`。
- Document / Settings 正文：`max-width: 760px`。
- 数据密集表格：允许使用内容区全宽。

### 5.3 首页重构建议

默认空数据库下，首页应展示：

- 页面标题：“上午好，测试管理员”或简单的“首页”。
- 主内容：“最近项目”；为空时使用标准 Empty，并提供“新建项目”。
- 次内容：进行中/已归档的紧凑统计行，可隐藏用户数量。
- 不展示“模板已就绪”“Server Actions 已连接”等开发者文案。
- 管理员提醒只在存在需要处理的事项时出现，不长期占位。

## 6. Notion 启发的视觉系统

根目录 `DESIGN.md` 主要分析 Notion 营销站，不能原样用于应用界面。本项目采用其原则，而不是照抄其营销组件。

### 6.1 视觉关键词

**温暖、纸张感、安静、清晰、轻密度、内容主导。**

### 6.2 色彩

- 页面画布：轻微暖灰，不使用临床式纯白铺满全屏。
- 内容表面：白色或与画布仅有很小明度差。
- 文本：暖黑/深灰，次要文本保持 WCAG 可读对比。
- 结构色：只保留一个蓝色，用于链接、焦点、选中和主动作。
- 状态色：成功、警告、错误使用语义 token，不把装饰色直接当状态。
- 深色模式不是反色；保持层级差、降低纯黑与纯白的刺激。

实现时只通过 `src/app/globals.css` 的语义 token 调整，不在业务组件内散落原始色值。

### 6.3 字体

- 中文 UI 默认优先 `Noto Sans SC`/系统中文无衬线，拉丁与数字可使用 Geist。
- 不引入 Notion 私有字体。
- 应用标题 24–32px；页面标题 24–28px；正文 14–15px；导航 14px。
- 下载的 `DESIGN.md` 中 40–64px 展示标题属于营销页面，不应用到工作台。
- 数字统计使用 tabular numerals；长文行长控制在 65–80 个拉丁字符的等效范围。

### 6.4 形状与层级

- 导航行和输入：6px 左右圆角。
- 内容卡/弹层：8–12px；不把所有容器做成胶囊。
- 默认层级依靠 1px hairline 和表面差；阴影只给菜单、弹窗、悬浮面板。
- 业务列表优先整行 hover/selected 状态，避免每条记录一个大 Card。

### 6.5 间距和密度

- 4px 基础网格；常用步进 4 / 8 / 12 / 16 / 24 / 32。
- 桌面导航行视觉高度 32–36px；移动触达区域至少 44px。
- 页面上下间距 24–32px；设置章节间距 32–40px。
- 紧凑不等于拥挤：同一组更近，不同组通过留白或 Separator 拉开。

### 6.6 动效

- hover/focus：120ms；面板进入：160–200ms。
- 只动画 opacity 和 transform；尊重 `prefers-reduced-motion`。
- 保存成功不做大面积动画，使用 toast 或字段旁的短暂状态。

## 7. 组件与状态规范

优先组合现有 shadcn 组件，不修改 `src/components/ui/` 与 `src/components/calendar/`。

| 场景 | 组件组合 |
| --- | --- |
| 主导航 | `Sidebar` + `SidebarGroup` + `SidebarMenu` |
| 用户入口 | `Avatar` + `DropdownMenu`；所有 Item 放在 Group 内 |
| 移动导航 | `Sidebar` 自带移动 Sheet 或明确的 `Sheet` |
| 设置导航 | 桌面链接列表；移动 `Item` 列表 |
| 设置表单 | `FieldGroup` + `Field`，选项组用 `ToggleGroup`/`RadioGroup` |
| 页面空状态 | `Empty`，不手写空白 Card |
| 加载 | route `loading.tsx` + `Skeleton` |
| 异步按钮 | `Button` + `Spinner` + disabled |
| 确认删除 | `AlertDialog` |
| 命令面板 | `Command` + `Dialog`，在业务域增多后启用 |
| 状态 | `Badge` 及语义 token |

必须覆盖：default、hover、focus-visible、active/selected、disabled、loading、empty、error、success、mobile、dark mode。

## 8. 模板基础设施清单

### 8.1 默认内核：必须有

| 能力 | 当前 | 下一步 |
| --- | --- | --- |
| 环境变量 schema | 已有 | 增加启动错误说明与示例校验 |
| 认证与会话 | 已有 | 设置中增加会话管理入口，若 Better Auth 能力允许 |
| 服务器端授权/DAL/DTO | 已有 | 继续作为不可回退的安全基线 |
| 数据库迁移与索引 | 已有 | 增加迁移前备份流程说明 |
| 健康检查 | 已有 | 关于页只显示窄化后的状态，不泄露路径 |
| 备份 | CLI 已有 | 增加恢复文档；UI 只做引导，不直接覆盖数据库 |
| 数据导出/导入 | 缺失 | 先提供 JSON/CSV 导出；导入必须预检、确认、可回滚 |
| 错误/404/加载/空状态 | 部分已有 | 统一视觉与可操作恢复 |
| 日志 | 仅 console | 增加服务端结构化日志、request/correlation id、敏感字段脱敏 |
| 审计 | 缺失 | 对登录、用户状态、危险数据操作记录最小审计事件 |
| 安全响应头/CSP | 缺失 | 依据部署方式提供安全默认值 |
| 限流 | 缺失 | 登录和高成本 mutation 至少进程内限流；注明单实例边界 |
| 测试 | 已有 | 增加设置路由、键盘导航、对比度和移动导航用例 |
| 可访问性 | 组件基础较好 | 加入 axe 或等效自动检查，并保留人工键盘检查 |
| 发布与升级 | README 初步具备 | 增加版本迁移、备份、回滚清单 |

### 8.2 按项目启用：不要默认塞入

- 邮件发送和邮箱验证。
- OAuth、Passkey、MFA。
- 多租户、组织、邀请、复杂 RBAC。
- 计费、订阅、支付。
- 对象存储、队列、定时任务。
- 云端分析、错误上报、OpenTelemetry 后端。
- PWA 离线缓存、多端同步、冲突解决。
- 国际化。

原则：模板提供清晰扩展点和文档，不为未发生的需求预付复杂度。

## 9. 模块边界

建议新增或重组为：

```text
src/
├─ app/(dashboard)/dashboard/
│  ├─ settings/                   设置路由与布局
│  └─ projects/                   示例业务路由
├─ components/shared/
│  ├─ app-shell/                  侧栏、顶栏、移动导航、用户菜单
│  └─ page-shell/                 页面宽度与标题模板
├─ features/settings/
│  ├─ navigation.ts               设置分区注册表
│  ├─ profile/
│  ├─ security/
│  ├─ appearance/
│  ├─ data/
│  └─ administration/
└─ features/projects/             可删除示例业务
```

导航项使用有类型的配置对象，包含 `title`、`href`、图标组件、分区和权限判定。不要用字符串图标映射，也不要让导航配置成为授权来源。

## 10. 实施顺序

### Phase 0：冻结基线

- 记录现有路由与 E2E 行为。
- 增加目标路由测试，先允许重定向。
- 确认未修改 `src/components/ui/` 和 `src/components/calendar/`。

### Phase 1：壳层与信息架构

- 重构侧栏、用户菜单、顶栏和页面宽度。
- 建立 settings layout 与导航。
- 添加旧路由重定向。

### Phase 2：设置中心

- 迁移个人资料和密码。
- 将现有偏好注册表做成外观设置 UI。
- 迁移用户和角色页面，并保持管理员鉴权。

### Phase 3：视觉系统

- 调整全局语义 token、排版、边框、圆角和阴影。
- 重构首页、项目列表、登录页、错误页。
- 移除业务界面的模板说明文案。

### Phase 4：基础设施补强

- 数据导出、恢复文档、结构化日志、审计事件、CSP 与限流。
- 增加无障碍和关键设置流程测试。

### Phase 5：模板打包

- 明确“内核”和“示例业务”的删除说明。
- 新项目检查清单、升级清单和可选能力决策表。

## 11. 完成标准

- 主侧栏中没有个人资料、用户、角色或系统状态。
- 从左下角用户入口最多两步到达任一设置页面。
- 普通用户看不到管理员设置，直接访问仍由服务器拒绝。
- 桌面、390px 移动宽度均无横向溢出，主动作和标题层级明确。
- 键盘可打开侧栏、用户菜单、设置导航和所有表单；焦点可见。
- 页面在空、加载、错误、成功、禁用与深色模式下都有明确状态。
- 首页不展示实现技术或模板就绪信息。
- `pnpm typecheck`、`pnpm check`、`pnpm test:unit`、`pnpm test:e2e` 通过。
